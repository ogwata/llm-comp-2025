# exp26-27: LoRAランク構成変更実験

**作成日:** 2026-02-28
**目的:** 0.760プラトーの突破
**提出予定:** 2回（残り25回 → 23回になる）

## 仮説

現在の構成（SFT r=64 / DPO r=8）はランクのバランスが悪い可能性がある。

- **SFT r=64は過大?** ベースモデルの汎化能力を過度に書き換え、DPOの改善余地を狭めている可能性
- **DPO r=8は過小?** preference信号を捉える容量が不足し、0.760で頭打ちになっている可能性
- **実験方針:** SFT r=16（軽量化）+ DPO r=16（拡大）で最適バランスを探る

## exp25からの教訓（適用済み）

- max_length=1024を維持（2048は逆効果: 0.739）
- DPO信号は出力の前半に集中しており、1024トークンで十分

## 代替案（exp26が不調の場合）

exp26のスコアが0.700未満に落ちた場合、SFT r=16が不適と判断し、以下の代替案を検討:

### 代替案A: exp2 SFT（r=64）のまま、DPO r=16のみ変更
- SFTは実績のあるexp2（r=64, 0.751）をそのまま使用
- DPOのみr=8→r=16に拡大
- SFTの変更リスクを排除し、DPOランク拡大の効果のみを測定

### 代替案B: exp2 SFT（r=64）のまま、DPO r=32に拡大
- DPOランクをさらに拡大（r=32, alpha=64）
- 容量不足が原因であれば、より大きな改善が期待できる

### 代替案C: DPO LR微調整（r=8のまま）
- LR=6e-7やLR=9e-7など未探索領域を試す
- ただし、exp21-23で7e-7〜8e-7が同等だったため改善の見込みは低い

## リスクと注意事項

1. **SFT r=16の懸念:** r=64→r=16で学習容量が1/4になる。構造化データの多様なフォーマット（5種類）を十分に学習できない可能性
2. **DPO r=16の期待値:** trainable parametersが約2倍になるが、同じデータ量（4,040件）では過学習のリスクもある
3. **提出管理:** 2回消費で残り23回。deadline(3/2 12:00)まで3日
4. **max_length=1024を厳守:** exp25の教訓。DPOでは1024が最適
