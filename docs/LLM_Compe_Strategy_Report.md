# 松尾研LLM開発コンペ2025：StructEval 0.8突破に向けたDPO最適化およびマルチLoRAマージ戦略ロードマップ

本報告書は、実験19（exp19）での知見を反映し、StructEvalベンチマークにおける「0.8突破」という野心的な目標を達成するための技術仕様書である。Qwen3-4Bのベース性能（67.04%）や、商用SOTAモデルであるGPT-4o（76.02%）の壁を打破するため、安定した `exp2` をベースモデルとしつつ、DPOによる「Raw Only」制約の徹底と、Task Arithmeticを用いたLoRA統合戦略を、段階的な検証ゲートを設けて実行する。

## 1. 戦略的目標：StructEval 0.8+ の実現

StructEvalは構文と構造を極めて厳格に評価するベンチマークであり、o1-miniですら平均75.58%に留まる難関である。しかし、Qwen3-4B-Thinking-2507に見られる「思考プロセスの最適化」が数学ベンチマーク（AIME25）で+15.7ポイントの劇的な向上（81.3%達成）をもたらした事実に鑑みれば、構造化タスクにおいても適切なDPO整列を施すことで0.8突破は十分に射程圏内である。

* **目標設定**: 変換タスク（Conversion）での8割超えを維持しつつ、生成タスク（Generation）におけるMarkdown混入を完全に排除することで「0.8突破」を目指す。
* **不整合の解消**: 実験19で露呈したMarkdown混入（79%）という「報酬ハッキング」を、拒絶空間（Penalty Space）の明示的な定義と機械的データ合成によって数理的に補正する。

## 2. データセット戦略：高品質ソースへの集約

LLMによるデータ合成を排除し、プログラムによる加工のみで学習データの純度を高める。

* **採用データセット**: `u-10bei/cot_512_v2` を唯一の正解ソースとする。`daichira` データセットはタグリークによる構文破壊（exp19以前の失敗）の原因となるため、使用リストから完全に除外する。
* **機械的加工（負例の生成）**: Pythonスクリプトを用い、正解JSONに対して「Markdownフェンス（json...）」「会話的接頭辞」「末尾解説」を付与したRejectedデータを生成し、DPOペアを構築する。

## 3. DPOハイパーパラメータ：安定と突破の二段構え

学習率 $LR=7 \times 10^{-7}$ を維持しつつ、$\beta$ 値によってモデルの「保守性」と「変革性」を使い分ける。

* **検証済み安定設定**: $\beta=0.2$。モデルの既存知識を保護し、急激な分布変化を抑制する。
* **攻撃的突破設定**: $\beta=0.1$。事前学習バイアス（助手らしさ）を強力に剥ぎ取り、「Raw Only」挙動を深層レベルで定着させる。

## 4. 実行ロードマップ：段階的検証と条件付き進行

残り30回の提出枠を無駄にしないよう、各フェーズに明確な「進行判断基準（Go/No-go）」を設定する。

### フェーズ0：基準点の再定義（提出1回）

* **アクション**: `CLAUDE.md` の優先アクションに従い、安定していた `exp11` を標準コード2で推論・評価する。
* **目的**: 評価環境の整合性を確認し、DPO改善の真のスタートラインを確定させる。

### フェーズ1：単一LoRA DPOによる限界突破（提出2〜10回目）

* **内容**: `u-10bei/cot_512_v2` ベースの「アンチ・フィラー/Markdown DPO」を `exp2` に対して実施。
* **目標**: スコア 0.76+ （GPT-4oレベル）の達成。
* **進行判断（Gate）**: 単一LoRAで 0.76 を超えた場合のみ、フェーズ2の「マルチLoRAマージ」へ進む。超えられない場合は、DPOデータセットの多様化と $\beta$ 値の再調整にリソースを集中させる。

### フェーズ2：役割別LoRAの個別学習（進行時：提出11〜20回目）

* **Adapter A (Format)**: Markdown/フィラー排除に特化したDPO LoRA。
* **Adapter B (Reasoning)**: 思考能力を構造化タスクに転移させるSFT LoRA。

### フェーズ3：Task Arithmeticによる能力統合（提出21〜30回目）

* **マージ手法**: `mergekit` を用い、**Task Arithmetic (TA)** または **TIES-Merging** を適用する。
* **具体的数式**: $W_{merged} = W_{0} + \lambda_{1} (LoRA_{A}) + \lambda_{2} (LoRA_{B})$ に基づき、推論能力と形式遵守の最適バランスを係数 $\lambda$ の探索によって特定する。

## 5. 遵守ルールと検証体制

* **推論コード**: 標準コード2（改変禁止）を絶対条件とする。
* **提出形態**: LoRAをベースモデルにマージ済みのフルパラメータモデルとしてアップロードする。
* **品質担保**: GitHubリポジトリ `ogwata/llm-comp-2025` 内のスクリプトで、提出前にバリデーションセットに対するMarkdown混入率を自動計測する。

---

本戦略は、商用トップモデルの壁（76%）を突破し、Qwen3-4Bのポテンシャルを「構造的正確性」に全振りすることで 0.8 という未踏の領域へ到達させるための精密な射撃計画である。
