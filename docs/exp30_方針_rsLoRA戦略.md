# exp30方針: rsLoRA + 正則化強化によるSFT改善戦略

**作成日:** 2026-03-01
**根拠:** Slackでの0.82超え・0.8超え報告者の知見

## 1. Slack情報の分析

### 投稿1（SFTのみで0.82超え）

核心は**「過学習防止こそが最重要」**という主張。

- Qwen3-4Bは素の状態で既に構造化データ出力の基礎能力を持つ
- v2データセットは約3,650件と少量 → 丸暗記しやすい
- validation lossを下げてもテストデータにフィットしない → 検証/テストの分布が異なる
- **rsLoRA**（Rank-Stabilized LoRA）を推奨。ランクは大きめ
- 低めの学習率が有効
- 過学習防止パラメータ（dropout, weight_decay）はGemini推奨より大きめが効く
- 勾配累積を増やして学習の質を向上
- DPOは大きな効果なし（我々の経験と一致）

### 投稿2（SFTのみで0.7→0.8）

最大の知見は**コンテキスト長の拡張**。

- MAX_SEQ_LEN拡張（512→1024）が0.7突破の決定打
- L4 GPU必須（T4は512が限界）
- 勾配累積の増加で学習ノイズ削減
- 0.8突破にはハイパーパラメータ以外の環境変数（LoRA設定等）の変更が必要
- dropout/weight_decay等の正則化強化が0.8の壁を越える鍵

## 2. rsLoRAとは何か

通常のLoRAとrsLoRAのスケーリングの違い:

- **通常のLoRA**: スケーリング = α/r → ランクを上げるほど1パラメータあたりの更新量が小さくなる
- **rsLoRA**: スケーリング = α/√r → ランクを上げても更新量が急激に縮小しない

exp26(r=16, 通常LoRA)が0.636に壊滅した理由:
r=64→16にしたことでスケーリング比が変わり（α/r = 128/16 = 8 vs 128/64 = 2）、学習ダイナミクスが崩壊した。rsLoRAならランク変更時のスケーリング変動が緩やかなため、大きいランクでも安定して学習できる。

大きいランク = より多くの独立した方向で重みを調整可能 = より精密な微調整が可能。

## 3. 我々の実験との整合性

| Slackの知見 | 我々の経験 | 整合するか |
|:--|:--|:--|
| 過学習防止が最重要 | exp5(epoch=2)で0.579、exp29(DPO ep2)で0.738 | 整合する |
| 低めのLR | exp1(2e-4)で0.675、exp2(5e-5)で0.751 | 整合する |

| 勾配累積増加 | grad_accum=8固定 | 未検証の軸 |
| dropout/weight_decay強化 | dropout=0, weight_decay=0.05固定 | 未検証の軸 |

**重要な発見**: 我々がこれまで変えてきたのはLR、epoch、DPOパラメータ、データセットだった。しかし0.8達成者が変えているのはrsLoRA、ランク、コンテキスト長、正則化であり、我々が手を付けていなかった軸。

## 4. exp30のパラメータ変更と根拠

| パラメータ | exp2 (0.751) | exp30 | 変更根拠 |
|:--|:--|:--|:--|
| rsLoRA | なし | **有効** | 大ランクでも安定学習できるスケーリング手法。0.82達成者が明示的に推奨 |
| LoRA rank | 64 | **128** | rsLoRAと組み合わせで、より精密な微調整が可能に |
| LoRA alpha | 128 | 128 | 維持（rsLoRAがスケーリングを自動調整） |
| MAX_SEQ_LEN | 512 | **1024** | 回答切れ防止。0.7突破の決定打として報告あり。L4 GPU必須 |
| LR | 5e-5 | **2e-5** | 過学習防止。「低めが有効」との報告 |
| dropout | 0 | **0.05** | 正則化強化。過学習の能動的な防止 |
| weight_decay | 0.05 | **0.1** | 「Gemini推奨より大きめが効いた」との報告 |
| grad_accum | 8 | **16** | 実効バッチサイズ16→32。勾配ノイズ削減、学習の質向上 |
| epoch | 1 | 1 | 維持（過学習防止） |
| データセット | v2 | v2 | 維持（v2が最良は確立済み） |

## 5. リスクと次のステップ

### リスク
- 複数パラメータを同時に変更するため、どの変更が効いたか特定しにくい
- rsLoRAがUnslothの現バージョンで正しく動作するか未確認
- L4 GPUの課金コスト

### exp30の結果に応じた次のステップ
- **0.8超え**: 成功。DPO追加を検討するかそのまま提出
- **0.76-0.8**: 改善あり。LR、dropout、weight_decayを微調整して追加実験
- **0.75以下**: rsLoRAまたはr=128が悪影響の可能性。r=64+rsLoRA、またはrsLoRA無しでSEQ_LEN=1024のみを試す
