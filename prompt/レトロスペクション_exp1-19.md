## 2. 成功した施策

### 2.1 SFTデータセットの選定：v2が最適解
- `u-10bei/cot_512_v2`（約3,650件）がSFT=0.751を安定的に達成
- LR=5e-5とLR=1e-4の両方で同一スコア（exp2, exp3）→ ロバスト
- v2以外のデータセット（v4, v5, daichira系）はすべて大幅に劣る

### 2.2 SFT+DPO多段階学習
- exp2（SFT best）をベースにDPOを適用する多段階手法が有効
- DPO LRの段階的最適化で着実にスコアが向上：
  - exp9 (LR=1e-7) → 0.725
  - exp10 (LR=5e-7) → 0.739
  - exp11 (LR=5e-7, β=0.2) → 0.742
- β値の増加（0.1→0.2）が小幅ながら効果あり

### 2.3 推論コードの互換性確認
- 標準コード1と標準コード2の差異は小さい（exp2: 0.751 vs exp16: 0.746）
- vLLMベースの標準コード2でもほぼ同等の性能を確認

## 3. 失敗した施策と教訓

### 3.1 daichiraデータセット：3回連続壊滅
| 実験 | データセット | スコア | 問題 |
|:----:|:-----------|:-----:|:-----|
| exp6 | daichira/hard-4k | 0.022 | tool_call汚染 84件 |
| exp13 | daichira/structured-5k-mix-sft | 0.064 | tool_call汚染 113件 |
| exp17 | daichira 5k + v4 hybrid | 0.056 | tool_call汚染（混合でも伝播） |

**教訓:** daichiraデータセットには`<tool_call>`タグが混入しており、モデルの出力パターンを根本的に破壊する。データ品質の問題であり、スキーマ変換やフィルタリングでは解決不可能。**今後daichiraへの投資は不要。**

### 3.2 Epoch増加による過学習
- exp5: v2でepoch=2にしたところ0.751→0.579に大幅悪化
- 約3,650件の小規模データセットでは1 epochが最適

**教訓:** 小規模データ（<5k）でのepoch増加は過学習リスクが高い。

### 3.3 DPO LRの上限
- exp12: DPO LR=1e-6で0.742→0.731に悪化
- DPO LRの最適範囲は5e-7付近。1e-6は過剰

### 3.4 Enhanced DPOの副作用
- exp19: β=0.2でenhanced-dpoを適用→0.701（Markdown汚染79%）
- 単純なrejected信号空間の拡張は「waterbed現象」を引き起こし、確率質量がMarkdownやフィラーに再分配される

**教訓:** DPOのrejectedパターンが単一次元だと、抑制された確率質量が別の望ましくないパターンに流れる。多次元的なrejected設計が必要。

## 4. 得られた知見

### 4.1 データセット品質 > ハイパーパラメータ
- v2→v5で-0.124、v2→v4で-0.245、v2→daichiraで-0.687～-0.729
- データセットの選択はLRチューニングの数倍のインパクト

### 4.2 DPO単体 < SFT単体
- DPO単体（exp7/8: 0.705-0.706）はSFT単体（0.751）に及ばない
- DPOはSFTで獲得した能力を微調整するツールであり、代替ではない

### 4.3 SFT+DPO多段階のスコア推移
```
exp2 (SFT only)       : 0.751  ← ベスト
exp9 (SFT+DPO LR=1e-7): 0.725  ← DPO適用で低下
exp10(SFT+DPO LR=5e-7): 0.739  ← LR最適化で回復
exp11(SFT+DPO β=0.2)  : 0.742  ← β調整で微増
exp12(SFT+DPO LR=1e-6): 0.731  ← LR過剰で悪化
```
- DPO適用時、初期は必ずSFTスコアから低下する
- LRとβの最適化で回復するが、SFTベストを超えるのは困難

### 4.4 推論コード間の差異は小さい
- 標準コード1 vs 標準コード2: 約0.005の差
- コードの違いよりもモデル品質のインパクトが圧倒的に大きい
